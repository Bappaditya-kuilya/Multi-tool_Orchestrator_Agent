# 10/10 Rebuild Plan — Multi-Tool Orchestrator Agent

**Goal:** Take the audited Multi-Tool Orchestrator Agent (5.0/10) to 10/10: zero critical/high security findings, zero crash paths, no dead code, packaged, documented, fully tested — plus a free-LLM layer so the agent runs at $0 on Groq / Gemini / OpenRouter (NL request → plan → execute), with an offline mock mode needing no keys.

**Target Audience:** Backend engineer evaluating permission-scoped tool delegation patterns
**Success Criterion:** Read architecture doc, run demos, extend with one new tool manifest + class in < 15 min, find no code path that crashes or escalates scopes.

---

## LLM Council Deliberation Summary

### Stage 1 — First Analysis
The plan should follow the existing `plan.md` structure but with clearer task decomposition, explicit verification checkpoints, and ponytail-aligned minimalism. Key principle: fix security/crash issues first (Phases 0-1), then wire/cut (Phase 2), then package (Phase 3), then free-LLM (Phase 3.5), then tests (Phase 4), then gate (Phase 5).

### Stage 2 — Multi-Perspective Critique

**Devil's Advocate:** The existing plan.md has 24 tasks across 7 phases but many tasks are underspecified. Task 1 "pass parent token into run_sub_task" sounds simple but touches orchestrator.py, executor.py, and all child orchestrator creation sites. Need explicit file/line references and test criteria.

**Skeptical Engineer:** Phase 3.5 (free-LLM) adds significant scope. The stdlib-only provider layer with urllib.request is ambitious — need to verify the OpenAI-compat and Gemini native APIs actually work without SDKs. Should de-risk by implementing MockProvider first (offline default) then add real providers incrementally.

**Maintainer/Operator:** The plan lacks CI integration details. GitHub Actions should run on every PR with pytest + compileall. Need to specify exact workflow file. Also the "zero warnings" gate requires fixing the utcnow deprecation warning in auditor.py.

**End User:** The "extend in 15 minutes" success criterion is great but needs a concrete test: add a new tool (e.g., "mock-time" with capability "time") via manifest + class + test, time the whole process.

### Stage 3 — Synthesis
**Final Plan Structure:** 8 Phases, ~30 tasks, each with explicit file targets, verification checklists, and anti-pattern guards. Prioritize: security fixes → crash fixes → wire/cut → packaging → free-LLM → test hygiene → final gate. Use ponytail: simplest fix that works, mark shortcuts with `ponytail:` comments.

## Anti-Pattern Guards (Ponytail)

| Anti-Pattern | Guard |
|--------------|-------|
| New dependency for stdlib task | Use `urllib.request`, `json`, `dataclasses`, `contextvars` only |
| Speculative abstraction | No interface with one implementation; no factory for one product |
| Boilerplate "for later" | Delete `GenericMockTool` (T14), delete `ConflictResolver` (T11) |
| Custom cache class | `@lru_cache` or nothing until profiler says otherwise |
| Complex retry logic | `retry_with_backoff` with 3 attempts, exponential backoff — 15 lines max |
| Framework for tests | `assert`-based self-checks or one small `test_*.py` per module |
